# Security

Ambitious maintains this module. If you believe you have found a security vulnerability, please tell us in private so we can fix it before it is discussed in public.

## How to report

Do not open a public GitHub issue for a vulnerability, and do not include live credentials, access tokens, or private account data in the report.

Use GitHub's private vulnerability reporting:

[Report a vulnerability](https://github.com/AmbitiousBots/ambitious-audit/security/advisories/new)

Please include:

- The version you tested, or the commit.
- What goes wrong, and what you expected instead.
- Enough detail for a maintainer to reproduce it on their own machine. A small fixture is more useful than a dump of a real account.
- Who is affected, and what an attacker could do with it.

If you cannot use private vulnerability reporting, contact the maintainers another way that is not a public issue, and say that the message is a security report.

## What happens next

We will acknowledge the report, work on a fix, and tell you when a release contains it. Please give us a chance to publish that fix before you write about the issue in public.

A report that is not a vulnerability, such as a bug in a rule or a mistake in the documentation, belongs in a normal GitHub issue.
